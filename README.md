# QR MedSecure API

A Django REST API for managing medicine inventory, dispatching machine commands, and collecting machine logs for a QR-based medication dispensing system.

## Overview

This API is designed to support a web dashboard and connected IoT/ESP32 device workflows. It provides endpoints for:

- Viewing medicine inventory
- Replenishing stock
- Queuing machine commands
- Polling pending instructions from an IoT device
- Recording machine activity and sensor logs

The project uses:

- Python 3
- Django
- Django REST Framework
- SQLite for local development

## Project Structure

- `api/` - API app containing models, serializers, views, and endpoint logic
- `core/` - Django project configuration and root URL routing
- `db.sqlite3` - Local SQLite database
- `manage.py` - Django management entry point

## Authentication

All API endpoints require an API key in the request header:

```http
X-API-Key: qr-medsecure-super-secret-key-123
```

If the header is missing or invalid, the API responds with `403 Forbidden`.

## Base URL

```text
http://localhost:8000/api/v1
```

## Endpoints

### 1) Get inventory

```http
GET /api/v1/inventory/
```

Returns the full medicine inventory.

Example response:

```json
[
  {
    "id": 1,
    "medicine_name": "Paracetamol",
    "stock_quantity": 42,
    "batch_number": "B-001",
    "updated_at": "2026-11-08T10:00:00Z"
  }
]
```

### 2) Refill medicine stock

```http
POST /api/v1/refill/
```

Request body:

```json
{
  "medicine_inventory_id": 1,
  "quantity_added": 10
}
```

Example success response:

```json
{
  "status": "success",
  "new_stock": 52
}
```

### 3) Send command to machine

```http
POST /api/v1/commands/send/
Content-Type: application/json
X-API-Key: qr-medsecure-super-secret-key-123
```

Complete request example:

```bash
curl -X POST \
  http://localhost:8000/api/v1/commands/send/ \
  -H "Content-Type: application/json" \
  -H "X-API-Key: qr-medsecure-super-secret-key-123" \
  -d '{
    "command_type": "DISPENSE",
    "motor_channel": 2,
    "parameters": "{\"steps\": 120, \"direction\": \"forward\"}"
  }'
```

Request body example:

```json
{
  "command_type": "DISPENSE",
  "motor_channel": 2,
  "parameters": "{\"steps\": 120, \"direction\": \"forward\"}"
}
```

Supported command types:

- `DISPENSE`
- `REFILL`
- `CALIBRATE`
- `TEST_IR`

Example success response:

```json
{
  "status": "success",
  "message": "Command queued for IoT machine",
  "data": {
    "id": 4,
    "command_type": "DISPENSE",
    "motor_channel": 2,
    "parameters": "{\"steps\": 120, \"direction\": \"forward\"}",
    "status": "PENDING",
    "created_at": "2026-11-08T10:05:00Z"
  }
}
```

Example validation error response:

```json
{
  "command_type": [
    "This field is required."
  ]
}
```

### 4) Poll pending machine instruction

```http
GET /api/v1/iot/poll/
```

Used by the IoT device to retrieve the next pending instruction.

Example response when a command is pending:

```json
{
  "status": "success",
  "command": {
    "id": 4,
    "command_type": "DISPENSE",
    "motor_channel": 2,
    "parameters": "{\"steps\": 120, \"direction\": \"forward\"}",
    "status": "PROCESSING",
    "created_at": "2026-11-08T10:05:00Z"
  }
}
```

If no command is available:

```json
{
  "status": "no_instruction"
}
```

### 5) Record machine logs

```http
POST /api/v1/logs/machine/
```

Request body:

```json
{
  "log_type": "INFO",
  "message": "Dispensing cycle completed successfully."
}
```

Example success response:

```json
{
  "status": "success",
  "message": "Log recorded"
}
```

## Data Models

### MedicineInventory

Represents available medication stock.

Fields:

- `medicine_name`
- `stock_quantity`
- `batch_number`
- `updated_at`

### CommandQueue

Stores queued actions for the IoT machine.

Fields:

- `command_type`
- `motor_channel`
- `parameters`
- `status`
- `created_at`

Status values:

- `PENDING`
- `PROCESSING`
- `COMPLETED`

### MachineLog

Stores logs generated by the device or backend.

Fields:

- `log_type`
- `message`
- `timestamp`

## Local Setup

1. Create and activate a virtual environment:

```bash
python -m venv venv
source venv/bin/activate
```

On Windows:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

2. Install dependencies:

```bash
pip install django djangorestframework django-cors-headers
```

3. Run migrations:

```bash
python manage.py migrate
```

4. Start the server:

```bash
python manage.py runserver 0.0.0.0:8000
```

## Notes

- This implementation is intended for local or private network use.
- The API key is hardcoded in the application for development convenience and should be replaced with environment-based secrets in a production deployment.
- CORS is enabled for local network access, which is useful for web dashboards and IoT clients.
